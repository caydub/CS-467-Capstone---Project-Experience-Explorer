# API Reference

**Project Experience Explorer — CS 467 Spring 2026**

This is a living document. Add new routes here as they are built.

---

## Overview

The app uses server-rendered pages via Flask and Jinja2 templates. There is no separate REST API — routes return HTML pages, not JSON. All data is passed from Flask routes directly to templates via `render_template()`.

Routes that modify data (forms, votes, comments) use HTTP POST. Routes that display data use HTTP GET.

---

## Authentication

Google OAuth 2.0 restricted to `@oregonstate.edu` accounts. Unauthenticated users can browse and read reviews. Authenticated users can submit reviews, edit their own reviews, vote on helpfulness, and comment.

## Routes

### Public Routes (no login required)

| Method | Route | Description | Template |
|--------|-------|-------------|----------|
| GET | `/` | Browse projects — search, filter, sort, paginate | `index.html` |
| GET | `/project/<project_id>` | Project detail — reviews paginated, term filter | `project_detail.html` |

**Query params — `GET /`:**

| Param | Type | Description |
|-------|------|-------------|
| `search` | string | Title search (LIKE %query%) |
| `sort` | string | `title` (default), `most_reviews`, `avg_score`, `highest_difficulty`, `lowest_difficulty`, `highest_workload`, `lowest_workload`, `highest_team_dynamics`, `lowest_team_dynamics`, `highest_recommendation`, `lowest_recommendation` |
| `min_difficulty` / `max_difficulty` | int 1–5 | Filter by average difficulty range |
| `min_workload` / `max_workload` | int 1–5 | Filter by average workload range |
| `min_team_dynamics` / `max_team_dynamics` | int 1–5 | Filter by average team dynamics range |
| `min_recommend` / `max_recommend` | int 1–5 | Filter by average recommendation range |
| `has_reviews` | `1` | Only show projects with at least one review |
| `page` | int | Page number (default 1, 10 per page) |

**Query params — `GET /project/<project_id>`:**

| Param | Type | Description |
|-------|------|-------------|
| `review_term` | string | Filter reviews to a specific term (e.g. "Spring 2026") — only shows terms that have reviews |
| `review_page` | int | Page number for reviews (default 1, 5 per page) |

### Auth Routes

| Method | Route | Description |
|--------|-------|-------------|
| GET | `/login` | Redirect to Google OAuth consent screen |
| GET | `/logout` | Clear session and redirect to homepage |
| GET | `/auth/callback` | OAuth callback — validates token, checks OSU email domain, creates or retrieves student record |

### Review Routes (login required)

| Method | Route | Description | Template |
|--------|-------|-------------|----------|
| GET | `/project/<project_id>/submit-review` | Review submission form | `submit_review.html` |
| POST | `/project/<project_id>/submit-review` | Submit a new review | — redirects to project detail |
| GET | `/review/<review_id>/edit` | Edit form for reviewer's own review (403 if not owner) | `edit_review.html` |
| POST | `/review/<review_id>/edit` | Save edits to a review (403 if not owner) | — redirects to project detail |

**Review fields (submit and edit):**
- `term` — quarter/year selected from dropdown (generated by `generate_terms()`)
- `difficulty`, `workload`, `team_dynamics`, `would_recommend` — int 1–5 (required)
- `ai_use` — optional: `Not used`, `Research / learning`, `Code generation`, `Debugging / troubleshooting`, `Multiple / other`
- `review_text` — string up to 4000 chars (required)

### Helpfulness Routes (login required)

| Method | Route | Description |
|--------|-------|-------------|
| POST | `/review/<review_id>/vote` | Toggle helpful (value=1) or not helpful (value=-1) vote. Submitting the same vote twice removes it; submitting the opposite flips it. |

**POST body:** `value` (1 or -1), `project_id` (for redirect)

**POST body:** `comment_text`, `project_id` (for redirect)

## Notes for Contributors

- Follow PEP 8 for all route functions
- Every route that queries the database must call `get_db_connection()` and close the connection when done
- Use `render_template()` for all responses — no raw HTML strings in routes
- POST routes that modify data should redirect after success (POST/Redirect/GET pattern) to prevent duplicate submissions on refresh
- Add new routes to this doc when you build them
